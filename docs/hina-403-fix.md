# 히나 v1.2.1 — 403 및 로컬 모션 검수 수정

## 확인한 원인

- GitHub Actions API 호출은 `shared/hina/state.js`의 `QAPoller` 한 곳에 있다.
  데스크톱 `desktop/src/app.js`와 웹 `shared/hina/dashboard.js`가 각각 사용한다.
- 기존 2분 조회는 클라이언트당 시간당 약 30회다. 앱·웹을 함께 사용하면 약 60회에
  수동 조회·재시작 요청이 추가된다. 무한 루프는 없지만 비인증 한도에 도달할 수 있다.
  사용자의 IP에서 한도를 소진한 모든 클라이언트까지 확인한 것은 아니다.
- ETag, 캐시, 제한 해제 시간이 메모리에만 있어 재시작하면 곧바로 재요청했다.
- 8종 WebP와 v2 목록은 설치 번들에 들어 있다. 연결 오류를 상위 시각 상태로 처리하면서
  IdlePlayer가 수동·랜덤 검수까지 거부한 것이 재생 실패의 원인이었다.

## 최소 변경

- 기본 조회 5분(클라이언트당 약 12회/시간), 수동 조회·동일 origin 탭·재시작에 간격 적용.
- ETag/검증된 QA 결과/다음 요청/403·429 제한 해제 시간을 localStorage에 저장한다.
  `Retry-After`와 `X-RateLimit-Reset`까지 기다리고 재시작해도 대기 시간을 유지한다.
- 정상 캐시 대기는 실시간 성공으로 표시하지 않는다. 제한 해제 후 조건부 요청으로 복구한다.
- CONNECTION_ERROR 표시와 진단을 유지하면서 로컬 모션 검수만 허용한다.
  WORK/ALERT 및 실제 이동 상태는 기존 우선순위를 유지한다.
- 캐릭터 PNG, 인사/걷기 GIF, 원격 에셋 정책과 10분 주기는 변경하지 않았다.

## 검증과 배포

- Node 테스트 29개 통과. 403→재시작→무요청 대기→제한 해제 후 1회 복구, ETag/캐시 재사용 포함.
- 기존 클릭·드래그·상태 전환과 원격 캐시 복구 8개 회귀 통과.
- 추가 브라우저 검사: 403·원격 에셋 차단 중 8종 로컬 디코딩, 랜덤 재생, 원본 비교,
  재시작 요청 억제와 연결 복구를 검사한다. 최종 실행 결과는 CI에도 기록한다.
- 위 검사 통과 후에만 v1.2.1 Windows 설치본 빌드를 요청한다. 실제 EXE의 403·8종 재생·재시작 검사를 CI에 추가했다.
- 이미 소진된 GitHub 한도를 앱이 즉시 해제할 수는 없다. 제한 해제 전에도 로컬 검수는 가능해야 한다.
