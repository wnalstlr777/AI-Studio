# 성능 및 네트워크 공통 QA 규칙 — v1.1

## 목표
게임 실행으로 인해 다른 브라우저 탭의 영상 재생, 네트워크 이용 및 시스템 반응성이 눈에 띄게 악화되지 않도록 한다.

## 검수 항목
1. **네트워크 요청량**: 초기 로딩과 정상 플레이 구간을 분리하여 요청 횟수, 전송량, 실패율을 측정한다.
2. **반복 다운로드**: 같은 리소스를 의도 없이 반복 요청하거나 캐시를 무시하는지 확인한다.
3. **WebSocket 안정성**: 재연결 횟수, 메시지 빈도, 송수신량 및 오류를 측정한다.
4. **렌더링 부하**: FPS, 긴 프레임, CPU 사용 및 가능한 환경에서 GPU 부하를 점검한다.
5. **백그라운드 동작**: 탭이 숨겨졌을 때 불필요한 렌더링·업데이트·네트워크 요청을 줄이는지 확인한다. 멀티플레이 연결 유지 등 필요한 동작은 명시한다.
6. **동시 사용성**: 게임 실행 전·중·후에 다른 탭의 동영상 버퍼링과 반응성을 비교한다.
7. **PC·모바일**: 성능 조건이 다른 환경에서 각각 검수한다.

## 자동 검수 원칙
- Playwright에서 네트워크 요청 수·전송량·실패 요청·WebSocket 이벤트를 기록한다.
- 최초 로딩과 일정 시간 정상 실행을 구분한다.
- 초기 경고 임계값은 잠정값으로 설정하고 실제 측정 후 조정한다.
- 브라우저 자동화만으로 다른 서비스의 버퍼링이나 GPU 사용량을 완벽히 판정할 수 없다. 별도 실기기 검수를 병행한다.
- 원인을 확인하지 않고 네트워크 사용량이나 GPU 과부하로 단정하지 않는다.
- 테스트가 실행되지 않은 항목은 **미검수**로 기록한다.

## Sea 최초 검수 시나리오
1. Sea 접속 후 초기 로딩 요청량 기록
2. 게임 실행 중 15초간 요청 횟수와 전송량 측정
3. 같은 리소스의 반복 요청 탐지
4. WebSocket 연결·재연결·메시지 빈도 확인
5. 탭을 백그라운드로 전환했을 때 추가 활동 비교
6. 실제 유튜브 버퍼링 재현 여부 별도 확인

## 성능 QA 카테고리

| 분류 | 검수 지표 | 판정 원칙 |
|---|---|---|
| 렌더링 | 평균 FPS, 프레임 타임 p95/p99, 긴 프레임, 드로우콜, 삼각형 수 | 평균뿐 아니라 끊김을 별도 경고 |
| GPU·리플렉션 | 반사 텍스처 해상도, 갱신 주기, 픽셀 비율, GPU 시간(측정 가능 시) | 그래픽 옵션별 비교, 실제 GPU 시간은 지원 환경에서 측정 |
| CPU·메모리 | 긴 메인 스레드 작업, JS 힙 변화, 지속 증가 추세 | 단발 측정으로 누수 확정 금지 |
| 네트워크 | 요청 수, 전송량, 실패율, 중복 다운로드, WebSocket 재연결/빈도 | 초기 로딩과 정상 플레이를 분리 |
| 실행 환경 | 데스크톱·모바일, 포그라운드·백그라운드, 다른 탭 동시 사용 | 자동화 결과와 실제 기기 결과 구분 |

### 공통 판정 상태
- **통과**: 해당 프로젝트 기준을 충족했고 실제 측정이 완료됨
- **주의**: 기준 근접 또는 일시적 성능 저하 감지
- **실패**: 확정된 기준 위반이나 재현 가능한 문제 발생
- **미검수**: 측정 기능이 없거나 아직 실행하지 않음

### 프로젝트별 기준
- 이 문서는 Sea와 HINA에 공통 적용한다.
- 수치 임계값은 프로젝트별 문서에 기록한다. 실측 없이 임의의 합격 기준을 확정하지 않는다.
- 성능 회귀 시 이전 버전과 동일 장치·해상도·조건에서 비교한다.
